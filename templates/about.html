How scoring works

Match score = {{ (cfg.W_SKILLS*100)|int }}% skill coverage of the job description + {{ (cfg.W_TFIDF*100)|int }}% TF-IDF text similarity. Recommendation: score ≥ {{ cfg.SHORTLIST_AT|int }} shortlist, < {{ cfg.REJECT_BELOW|int }} reject, otherwise borderline. These weights and thresholds are fixed design choices (editable at the top of resume_parser.py), not learned from data.

Known limits

  • The trained model reached CV ROC-AUC {{ meta.get('cv_roc_auc','n/a') }} on dataset.csv ({{ meta.get('n_rows','?') }} rows). Labels follow the dataset-generation rule documented in generate_dataset.py, so treat the model as a demonstration. It is shown for reference only and does not decide anything.
  • NLP engine: {{ 'spaCy (en_core_web_sm) lemmatisation + TF-IDF' if cfg.SPACY_ACTIVE else 'regex tokenisation + TF-IDF (spaCy not installed)' }}.
  • Skill matching uses a fixed vocabulary; skills outside it are invisible. Experience and education are heuristic estimates from text.
  • Scanned (image-only) PDFs cannot be read.
  • Bias on gender, age and name has not been audited because the dataset has no such fields. Names are never used in scoring.
  • A human must review every decision. Do not use as the sole selection criterion.
